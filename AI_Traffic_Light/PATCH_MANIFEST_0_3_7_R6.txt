AiTL V037 R6 — quality-preserving TCP camera repair
==================================================

Version remains: 0_3_7

Passed baseline remains: 0_2_4

Runtime changes
---------------
- Preserve configured JPEG quality and resolution across TCP pressure/failures.
- Remove the R2/R4 3.8–5 KB payload target, partial-send target learning,
  automatic q=50 compression escalation, local oversize rejection and runtime
  resolution downshift/recovery.
- Use one PSRAM framebuffer with CAMERA_GRAB_WHEN_EMPTY; keep 20 MHz XCLK.
- Keep persistent ATL1 / aitl-tcp-jpeg-v1 transport and non-blocking vectored
  sendmsg path.
- Relax send guardrails to 700 ms no-progress / 1500 ms total, with
  1200 / 2000 ms connection warmup.
- Flush the pending one-buffer frame when a new TCP client connects.
- Keep freshness-first scheduling; achieved FPS may fall rather than queue old work.
- Add RSSI, BSSID, channel, slow-send and ESP Wi-Fi recovery telemetry.
- Existing PC reconnect/session-recovery implementation is retained.
