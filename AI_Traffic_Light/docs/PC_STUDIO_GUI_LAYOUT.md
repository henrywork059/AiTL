# PC Studio GUI Layout — V021 candidate

The PC Studio keeps the established sidebar + page-content layout. V021 adds occupancy analytics and counting regions on top of the V020 camera/capture/zone feature set without restructuring the application.

## Global layout

```text
Operate
- Dashboard          current version, smoke status, candidate scope
- Live AI            camera/simulation frame + detections + saved zones + compact simulated signal
- Cameras            receiver + controllable synthetic scene

Traffic setup & analytics
- Zones              persistent polygon editor; includes analytics-only counting regions
- Logic              live frame/zone counts + simulation recommendation
- Analytics          recorded pedestrian/vehicle occupancy plot + summaries/export/reset

Data & model
- Capture            persistent frame capture + delete-latest action
- Review / Label     browse/delete captures + manual boxes + managed YOLO build
- Train              local training + convergence plot + early stopping
- Models             model registry/load/default/delete

System
- Settings           persistent runtime settings
- Logs               recent real backend log buffer
```

## Traffic Analytics page

The Analytics page can select whole-frame occupancy or any configured non-ignore region, then show 1-minute, 5-minute, 15-minute, 1-hour, 6-hour, or all-retained history. It includes:

- pedestrian and vehicle time-series lines;
- current, average, and peak occupancy;
- peak timestamps;
- busiest-region summary;
- simulation phase-change context;
- CSV export;
- explicit analytics-history clear action.

Counts are sampled occupancy rather than unique passage counts.

## Zone Editor

`counting_region` is available in the same camera-aligned polygon editor. Multiple counting regions can be created and may overlap. Their counts are analytics-only; they do not change the simulation phase recommendation.

## Live AI

Saved counting regions use the existing zone overlay path and remain presentation-only. Detection/inference semantics are unchanged.

## Runtime history

Traffic analytics history is generated by the backend while it is running and stored under `outputs/traffic_history/`. It is local runtime data, not part of source patches.

## Safety boundary

No GUI surface sends commands to physical traffic lights. Traffic phases and recommendations remain supervised simulation/display output only.
